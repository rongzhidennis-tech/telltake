# Project backup and recovery

Choose **Back up project…** in the project window and give the backup a new
`.easycut` filename outside the original package. The app saves a consistent
database snapshot with `manifest.json`. It does not copy original clips, caches
or rendered videos. Keep original media separately. Do not copy only an open
`state.sqlite` file by hand: recently committed work may still be in its journal.

Open the backup normally. Transcript, analysis history, cuts, corrections, edit
provenance and current selections remain saved. A missing `cache/` or `exports/`
folder is not corruption. Missing or corrupt extracted audio is disposable and
can be regenerated by a later requested operation; opening does not start analysis
or contact a provider.

**Recovery status…** refreshes source validation and checks cached audio and export
references. Missing/moved outputs are stale; changed outputs fail the saved
fingerprint check. Unreadable, unverifiable legacy and unfinished exports are
identified separately. These warnings do not rewrite successful export records or
remove saved edits. File checks can take time for large videos and run off the UI
thread. They are observations, not a promise that a file cannot change afterward.

Missing originals remain listed in the project. Use **Relink selected clip…** to
choose the original at its new location. A plausible filename is insufficient:
fingerprint and metadata must match. Available ranges remain playable, and full
preview/export require only the originals used by the selected cut.

No automatic retry of unfinished work, search for substitute files or broad
temporary-file cleanup is performed. See
[ADR-092](../decisions/ADR-092-canonical-backup-and-recovery.md).
